Core Data Structures:
├─ ReconciliationStatus (Enum)
│  ├─ SYNCED: Reconciliação bem-sucedida
│  ├─ DIVERGENT: Valores divergem
│  ├─ UNKNOWN: Status indeterminado (MT5 offline, trade não registrado)
│  ├─ DUPLICATE: Trade já reconciliado
│  └─ TIMEOUT: Timeout na operação
│
├─ OutcomeType (Enum)
│  ├─ CLOSED: Trade fechado com sucesso
│  ├─ PARTIAL: Fechamento parcial
│  ├─ REJECTED: Rejeitado pela broker
│  └─ ABANDONED: Abandonado (timeout, etc)
│
├─ TradeOutcome (frozen dataclass - Value Object)
│  ├─ trade_id: str (UUID)
│  ├─ symbol: str (ex: "WIN$N")
│  ├─ side: str ("BUY" ou "SELL")
│  ├─ quantity: int (validado: > 0)
│  ├─ entry_price: float (validado: > 0)
│  ├─ exit_price: Optional[float]
│  ├─ timestamp_entry: datetime
│  ├─ timestamp_exit: Optional[datetime]
│  ├─ status: OutcomeType
│  ├─ pnl: Optional[float]
│  ├─ commission: float (default 0.0)
│  └─ metadata: Dict[str, Any]
│
└─ ReconciliationResult (dataclass)
   ├─ trade_id: str
   ├─ reconciliation_status: ReconciliationStatus
   ├─ timestamp: datetime (quando a reconciliação ocorreu)
   ├─ mt5_outcome: TradeOutcome (outcome reportado pelo MT5)
   ├─ local_outcome: Optional[TradeOutcome] (outcome registrado localmente)
   ├─ divergences: List[str] (descrições das discrepâncias)
   ├─ audit_log: Dict[str, Any] (trilha de auditoria estruturada)
   ├─ is_synced() -> bool (helper para verificar status)
   └─ to_dict() -> Dict (serialização para JSON)

Core Methods Implemented:
├─ reconciliar(mt5_outcome, local_outcome) -> ReconciliationResult
│  └─ Compara outcomes, detecta divergências, gera auditoria
│  └─ Handles: SYNCED, DIVERGENT, UNKNOWN status
│  └─ Validações: Timestamps (tolerância 2s), volume, preços
│
├─ reconciliar_batch(mt5_outcomes, local_outcomes) -> List[ReconciliationResult]
│  └─ Processa batch de trades (até 1000+ em <2s)
│  └─ Handles: None values in local_outcomes (aloca automaticamente)
│  └─ Validação: Tamanho das listas deve corresponder
│
├─ _detectar_divergencias(mt5, local) -> List[str]
│  └─ Compara: quantity, entry_price, exit_price, timestamps
│  └─ Retorna lista de divergências encontradas
│
├─ _validar_timestamps(ts1, ts2) -> bool
│  └─ Valida diferença entre timestamps (tolerance: ≤2000ms)
│  └─ Crítico para sincronização MT5-Local
│
├─ _gerar_audit_trail(trade_id, status, divergences) -> Dict
│  └─ Cria log estruturado com timestamp e detalhes
│  └─ Usar para compliance e troubleshooting
│
├─ _persistir_resultado(result) -> None
│  └─ Armazena em memória (Dict) por enquanto
│  └─ Próximo passo: persistir em SQLite
│
└─ _validar_saida_basica(outcome) -> bool
   └─ Valida invariantes básicas (quantity > 0, prices > 0)

ARCHITECTURE & DESIGN PATTERNS
═══════════════════════════════════════════════════════════════════════════════

Design Patterns Aplicados:

1. Value Object Pattern (TradeOutcome)
   └─ Frozen dataclass, imutável, validação em __post_init__
   └─ Garante integridade de dados através do pipeline

2. Domain-Driven Design (DDD)
   └─ TradeOutcome = Aggregate Root / Value Object
   └─ ReconciliationStatus = Bounded Context (Reconciliation)
   └─ Separação clara entre domain e infrastructure

3. Service Pattern (TradeOutcomeReconciler)
   └─ Single Responsibility: apenas reconciliar trades
   └─ Tipo: Application Service (orquestra operação)
   └─ Persistência delegada a _persistir_resultado()

4. Result Pattern (ReconciliationResult)
   └─ Retorna objeto com status + detalhes, não throw exceptions
   └─ Facilita tratamento de outcomes desconhecidos (UNKNOWN status)
   └─ Audit trail integrado

5. Clean Architecture
   └─ Domain layer: Value Objects, Enums, Exceções
   └─ Application layer: Service, Use Cases
   └─ Infrastructure layer: (future) Repository, Adapters

Performance Considerations:
├─ Batch processing: O(n) complexity, ~0.002s por trade
├─ Timestamp tolerance: 2000ms (configurável via constructor)
├─ In-memory storage: Dict lookup O(1)
├─ Future: SQLite persistence com indexes em trade_id
